# Postman collection

| File | Purpose |
|---|---|
| `SecureShareFR.postman_collection.json` | All API requests with assertions and an automatic CSRF pre-request script |
| `SecureShareFR.postman_environment.json` | Local development: API `:4000`, authority `:7000` |
| `SecureShareFR.postman_environment.https.json` | Full Docker stack over HTTPS (`https://localhost`) |

## Import

1. Import the collection and **both** environments into Postman.
2. Select `SecureShareFR Local` for `npm run dev`, or `SecureShareFR HTTPS (Docker)` for the compose stack.
3. Run folders in order: **1. Health & Meta** → **2. Auth & Sessions** → **3. Attribute Authority** → …
4. Every state-changing request gets `X-SecureShare-CSRF: 1` from the collection-level pre-request script. Two requests intentionally remove it to prove the 403 response.

## HTTPS notes

The local Docker stack uses a self-signed certificate generated by `sh deploy/nginx/gen-local-cert.sh`. Either:

- import `deploy/nginx/certs/server.crt` into Postman's trusted CA store (Settings → Certificates → CA Certificates), **or**
- for local testing only, turn off *SSL certificate verification* in Postman Settings.

Never disable certificate verification against a real deployment.

## Swagger alternative

The same API is documented interactively at `http://localhost:4000/docs` (direct API) or `https://localhost/docs` (Docker). Assets are served from the API itself — no CDN is used, so the strict Content Security Policy still applies. The raw document is at `/api/openapi.json`.
